# Review — performance lens — feat/ask-ai-handoff

Range: `main...HEAD` (merge-base c5166893ac2d8f7603b715cc2f5f4a74ebe3218a)
Lens: performance only (hot paths, UI-thread blocking, redundant work, memory growth, unbounded I/O).

## Findings

### 1. Handoff temp files are never deleted (LOW)
Where: `internal/harness/harness.go` — `PromptFile` (writePromptFile / Execute).
Evidence: `PromptFile` creates `tsk-prompt-*` via `os.CreateTemp` and deliberately never
removes it. Every handoff (CLI and TUI) leaves one file in the OS temp dir. On hosts
where `/tmp` is not a per-boot tmpfs or not aggressively reaped, these accumulate
without bound.
Why it matters: performance/maintainability — unbounded disk artifacts.
Fix: acceptable as designed, but if accumulation is a concern, have the harness/launcher
own cleanup (e.g. delete after the child exits, or write into a tsk-owned temp dir with a
bounded-retention sweep). At minimum document the growth.

### 2. `exec.LookPath` probes run on the UI thread when opening the picker (LOW)
Where: `internal/tui/askai_modal.go:31` `openAskAI` → `harness.Detect` →
`detectedBuiltins` (`internal/harness/harness.go`).
Evidence: `openAskAI` is called synchronously from `handleListKey`/`handleKanbanKey`/
`handleDetailKey` inside `Update`. `detectedBuiltins` calls `lookPath` for all 6 builtins
(6 × PATH entries stat calls) on the Bubbletea UI goroutine, per `a` keypress.
Why it matters: blocking call on the UI thread; negligible for a normal PATH, but the
detection result is stable within a session and need not be recomputed per open.
Fix: detect once (at startup or lazily and cache in the Model) and reuse; or move
detection into the returned `tea.Cmd` so it runs off the UI goroutine.

### 3. Config file parsed twice per Load (LOW)
Where: `internal/config/config.go` `Load` / `decodeHarnesses`.
Evidence: the file is now decoded twice — once into `scalarConfig`, once into
`map[string]any` for the harness salvage — where the old code did a single
`toml.DecodeFile`. Startup/CLI-invocation only, so the absolute cost is tiny.
Why it matters: redundant work; not on any hot path.
Fix: none required; keep as-is unless Load ever moves onto a hot path.

### 4. Redundant project lookup after GetTask in CLI (LOW)
Where: `internal/cli/cli.go` `cmdAsk` → `askStatuses` → `database.GetProject`.
Evidence: `GetTask` already joins the project, and `askStatuses` issues a second query
for the same row. One-shot CLI path.
Why it matters: extra DB round-trip; negligible.
Fix: reuse the project data already joined onto the task if available.

## Non-findings (checked)
- `askLaunchCmd` runs the handoff (temp write + spawn) inside the returned `tea.Cmd`,
  which Bubbletea executes off the UI goroutine — no UI blocking.
- `renderAskAIModal` runs per-frame while open but iterates a tiny list; consistent with
  the other modals.
- `go func(){ cmd.Wait() }()` is one goroutine per handoff that exits with the child — bounded.
